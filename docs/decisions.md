# Решения (ADR) — КБЖУ-трекер

> Журнал значимых технических и продуктовых решений: что выбрали, почему, какие последствия. Каждая запись — короткий ADR. Новые решения добавляй сверху.

---

## ADR-008 · Авторизация — Supabase Auth через OAuth (Google/Apple)
**Контекст:** для включения RLS нужна привязка строк к пользователю (`auth.uid()`); аудитория 15–25 ценит вход без паролей.
**Решение:** Supabase Auth с OAuth-провайдерами (Google, при желании Apple). Вход в один тап, без паролей и их восстановления.
**Последствия:** идентичность переходит с целочисленного `id` на `uuid = auth.uid()` → нужна миграция схемы и переписывание `db.js` на авторизованного пользователя. Провайдер настраивается в дашбордах (Supabase + Google Cloud) — это ручной шаг. План — `docs/auth-rollout.md`. Разблокирует ADR-007 (включение RLS).

## ADR-007 · RLS в Supabase временно выключен
**Контекст:** прототип без авторизации, один тестовый пользователь.
**Решение:** Row Level Security отключён (`supabase/rls_disable.sql`).
**Последствия:** данные не изолированы между пользователями — **нельзя пускать реальных людей**, пока не включим RLS и не добавим auth. Это блокер перед публичным запуском.

## ADR-006 · Бэкенд — Supabase (managed PostgreSQL)
**Контекст:** нужно сохранять данные и синхронизировать между устройствами; объём — десятки пользователей.
**Решение:** Supabase (PostgreSQL + готовое API и будущая авторизация).
**Последствия:** не нужно держать свой сервер; схема — `supabase/schema.sql`. Под текущий объём бесплатного тарифа хватает с запасом. Альтернативы (свой Node+Postgres, SQLite) отклонены как лишняя работа/потолок по синку.

## ADR-005 · Персистентность: переход с localStorage на БД
**Контекст:** localStorage живёт в одном браузере, нет синхронизации.
**Решение:** хранить состояние в Supabase; `boot()` гидрирует `state` из БД.
**Последствия:** данные доступны с разных устройств; появляется сетевой слой `db.js`.

## ADR-004 · Single-file прототип → Vite-проект
**Контекст:** `prototype_v1.html` разросся до ~1.4к строк в одном файле.
**Решение:** разбить на ES-модули, собрать Vite + `vite-plugin-pwa`.
**Последствия:** поддерживаемая структура, PWA-манифест, деплой на GitHub Pages. Старые single-file версии — в `../../archive/`.

## ADR-003 · Дизайн — светлый монохромный glassmorphism
**Контекст:** аудитория 15–25, нужен свой визуальный язык, не копия Fitia.
**Решение:** монохром + матовое стекло, акцент-графит, micro-анимации.
**Последствия:** отличие от конкурента-референса; единый стиль в `styles/main.css`.

## ADR-002 · Норма КБЖУ — временной ряд с адаптивной коррекцией
**Контекст:** формула Миффлина даёт оценку, а не точность.
**Решение:** хранить историю нормы; корректировать по фактической динамике веса (`calcCorrection`, лимиты ±300 ккал).
**Последствия:** норма «подстраивается» под реальный результат — ядро ценности продукта. Требует таблицы `norm_history`.

## ADR-001 · Стек — PWA-first, затем нативка
**Контекст:** быстро проверить спрос дешевле всего вебом.
**Решение:** PWA (Vite, чистый JS) сейчас; Capacitor → нативка позже.
**Последствия:** одна кодовая база, мгновенные обновления; потолок — web-push на iOS (триггер перехода на нативку). Подробности — в `../../Концепция_приложения_КБЖУ.md`.
