# Архитектура — КБЖУ-трекер (my-pwa)

> Как устроен код этого репозитория. Высокоуровневая продуктовая архитектура (Claude-агенты, коннекторы) — в планинг-папке: `../../АРХИТЕКТУРА_РЕШЕНИЯ.md`. Схема БД — `../../СХЕМА_БД.md`.

## Общая картина

Клиентское одностраничное PWA на чистом JS + ES-модулях, собирается Vite. Состояние держится в одном объекте `state` (src/state.js). Бизнес-логика расчёта нормы изолирована в `calc.js`. Персистентность — Supabase (PostgreSQL); раньше был localStorage, теперь данные в облаке. Деплой — статика на GitHub Pages.

```
Пользователь
   │
   ▼
PWA (Vite, src/)
   ├── state.js ........ единый источник истины + справочники DB/WDB
   ├── calc.js ......... чистая математика КБЖУ (тестируемая)
   ├── pages/* ......... экраны: onboarding, plan, progress, coach, profile
   ├── components/* .... шторки ввода
   ├── db.js / supabase.js ... доступ к данным
   └── main.js ......... boot(), маршрутизация табов
   │
   ▼
Supabase (PostgreSQL)
   profiles · diary_entries · weight_logs · workouts · norm_history
```

## Поток данных

1. `boot()` в `main.js` инициализирует Supabase-клиент и пытается загрузить профиль пользователя.
2. Если профиль есть — онбординг пропускается, `state` гидрируется из БД, открывается «План».
3. Любое действие (запись еды, тренировки, веса) обновляет `state`, перерисовывает экран и пишет в Supabase через `db.js`.
4. Норма КБЖУ считается в `calc.js` (формула Миффлина → TDEE → цель). При накоплении ≥2 недель данных по весу `calcCorrection()` предлагает скорректировать норму; применённая коррекция уходит в `norm_history`.

## Ключевые модули

**state.js** — мутабельный объект `state` (профиль, цели, дневник, тренировки, лог веса, история нормы) + статические справочники `DB` (продукты с КБЖУ на 100 г) и `WDB` (типы тренировок, ккал/мин).

**calc.js** — чистые функции без побочных эффектов:
- `calcTDEE()` — базовый обмен по Миффлину × коэффициент активности.
- `computeNorm()` — суточная норма ккал и БЖУ под цель (профицит/дефицит/поддержание).
- `calcCorrection()` — адаптивная коррекция нормы по фактической динамике веса, с лимитами безопасности (±300 ккал, не ниже мин. калоража).
- `recalcNorm()` — пересчёт при смене цели/активности.

**db.js / supabase.js** — слой доступа к данным; CRUD по таблицам Supabase.

**pages/** и **components/** — слой представления; рендер через глобальные `window.*`-функции (компромисс без стейт-менеджера).

## Известные ограничения (прототип)

- RLS в Supabase выключен, авторизации нет — данные не изолированы по пользователям (см. `decisions.md`).
- `state` глобален и мутабелен — осознанный выбор скорости разработки над строгостью.
- Тесты пока покрывают только `calc.js` (математику); UI — вручную.
