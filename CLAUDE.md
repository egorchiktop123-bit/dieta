# CLAUDE.md — репозиторий КБЖУ-трекера (my-pwa)

> Это **код-репозиторий** (Vite PWA, задеплоен на GitHub Pages). Здесь — правила работы с кодом.
> Продуктовый и стратегический контекст (концепция, аудитория, риски, бэклог) живёт в master-документе планинг-папки: `../CLAUDE.md`. Не дублируй стратегию здесь — ссылайся на неё.

---

## Что это

Прогрессивное веб-приложение (PWA): считает суточную норму калорий и БЖУ под цель пользователя, ведёт дневник питания и тренировок, отслеживает вес и адаптивно корректирует норму. Бэкенд — Supabase (PostgreSQL). Аудитория и продуктовые принципы — в master-CLAUDE.md.

## Стек и команды

- **Сборка:** Vite 5 + `vite-plugin-pwa`. Чистый JS, ES-модули, без фреймворка.
- **Бэкенд:** Supabase (`@supabase/supabase-js`).
- **Деплой:** GitHub Pages через `.github/workflows/deploy.yml`.

```bash
npm install      # зависимости
npm run dev      # localhost:5173
npm run build    # сборка в dist/
npm run preview  # предпросмотр сборки
npm test         # юнит-тесты (Vitest)
```

## Карта кода (`src/`)

| Файл | Ответственность |
|------|-----------------|
| `state.js` | Единый объект `state` (источник истины на клиенте) + справочники `DB` (продукты), `WDB` (тренировки) |
| `calc.js` | Чистая математика КБЖУ: `calcTDEE`, `computeNorm`, `calcCorrection`, `recalcNorm`. **Без побочных эффектов** — здесь всё юнит-тестируемо |
| `db.js` | CRUD к Supabase (профиль, дневник, вес, тренировки, история нормы) |
| `supabase.js` | Инициализация клиента Supabase |
| `utils.js` | Хелперы (формат, конвертация единиц, анимации) |
| `main.js` | `boot()`: грузит профиль из Supabase, пропускает онбординг для вернувшихся, навешивает табы |
| `pages/{onboarding,plan,progress,coach,profile}.js` | Экраны. Рендер через паттерн `window.*` |
| `components/sheets.js` | Нижние шторки (ввод еды/тренировки/веса), сохраняют в БД |
| `styles/main.css` | Светлый монохромный glassmorphism |

## Паттерны и соглашения

- **Источник истины — `state`.** Все экраны читают/пишут общий `state`, затем рендерят. Логика расчёта нормы вынесена в `calc.js` и не должна дублироваться в экранах.
- **Cross-module рендер через `window.*`.** Экраны вызывают друг друга через глобальные функции (`window.renderPlan` и т.п.) — это осознанный компромисс без сборщика состояний. Сохраняй паттерн, не тащи лишних зависимостей.
- **Норма — временной ряд, не одно число.** Коррекция нормы по динамике веса (`calcCorrection`) — ядро продукта. Не упрощай до «посчитал один раз».
- **Всё в метрике** (кг, см, граммы). Имперские единицы — только отображение.
- **КБЖУ-числа не выдумывает ИИ** — берутся из базы/расчёта. ИИ только парсит и советует.
- **Безопасность:** API-ключи не коммитим. RLS в Supabase сейчас **выключен** (прототип без авторизации) — это временно, см. `docs/decisions.md`.

## Перед коммитом

См. `guardrails/coding-rules.md` и `guardrails/review-checklist.md`. Кратко: `npm run build` проходит, `npm test` зелёный, формулы КБЖУ не сломаны, единицы в метрике, ключи не попали в репозиторий.
