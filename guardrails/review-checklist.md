# Чек-лист ревью

Пройди перед мержем любого изменения. Цель — поймать регрессии в критичном (математика КБЖУ, данные, безопасность) до того, как их увидит пользователь.

## Корректность
- [ ] `npm run build` проходит без ошибок и предупреждений
- [ ] `npm test` зелёный
- [ ] При правках `calc.js` — обновлены/добавлены тесты, эталонные числа осознанно пересчитаны, а не «подогнаны»
- [ ] Граничные случаи: нулевой/пустой дневник, первый день без замеров веса, цель = поддержание

## Данные и логика
- [ ] КБЖУ берётся из базы/расчёта, не выдумано
- [ ] Всё в метрике; имперское — только отображение
- [ ] Запись/чтение идёт через `db.js`, не напрямую в Supabase из экрана
- [ ] `state` остаётся единственным источником истины

## Безопасность
- [ ] В диффе нет ключей, токенов, секретов
- [ ] Не ослаблены ограничения доступа без причины (помним: RLS ещё выключен — не «закрепляем» это как норму)

## UX / продукт
- [ ] Экран понятен без инструкции (принцип простоты из master-CLAUDE.md)
- [ ] Не сломаны анимации/состояния (счётчики, конфетти, шторки)
- [ ] Изменение согласуется с концепцией (`../../Концепция_приложения_КБЖУ.md`)

## Гигиена
- [ ] Нет закомментированного мусора и `console.log` в проде
- [ ] Обновлены доки, если поменялось поведение (`docs/`, `decisions.md`)
